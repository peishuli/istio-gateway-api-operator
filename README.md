# Istio Gateway API Operator

A Kubernetes operator that simplifies exposing services through the Istio Gateway API. Define a single `Route` resource and the operator generates all the underlying resources (HTTPRoute, VirtualService, DestinationRule, EnvoyFilter) automatically.

## Why

The Kubernetes Gateway API with Istio requires managing multiple resource types to expose a single service — HTTPRoutes for routing, VirtualServices for timeouts/CORS, DestinationRules for TLS backends, EnvoyFilters for body size limits, plus HTTP→HTTPS redirects. This operator collapses all of that into one namespaced `Route` resource.

## Features

These are the baseline capabilities available in controller mode. In this mode, users can rely on the single `Route` CRD workflow without enabling additional operator-mode guardrails.

- **Multi-host/path routing** — Define multiple rules in a single Route, each mapping a host+path to a backend service
- **Automatic HTTP→HTTPS redirect** — Per-host 301 redirect HTTPRoutes generated by default
- **Request timeout** — Configurable per-Route timeout via Istio VirtualService
- **Request body size limiting** — Max body size enforcement via Istio EnvoyFilter (per-rule, per-vhost)
- **CORS policy** — Full CORS configuration (origins, methods, headers, max age) via Istio VirtualService
- **HTTPS backend support** — Automatic DestinationRule with TLS origination + `insecureSkipVerify` for backends serving TLS (e.g., Rancher, NeuVector)
- **Custom gateway reference** — Override the default gateway name/namespace per Route
- **Automatic resource cleanup** — OwnerRef-based GC for same-namespace resources, finalizer-based cleanup for cross-namespace resources

## Advanced Features

The following capabilities are the project's operator-mode features. They are additive and optional: teams can run in a minimal controller mode using only the core `Route` reconciliation, or enable these advanced behaviors for stronger guardrails, resilience, and automation.

- **Admission Webhooks** — Mutating webhook auto-injects default gateway refs; validating webhook rejects hosts that violate Gateway hostname patterns and rejects conflicting Routes (same gateway+host+path).
- **Multi-phase Status** — `status.phase` state machine implemented (`Pending`/`Provisioning`/`Active`/`Degraded`). Reconciliation now gates on backend readiness before generating managed resources.
- **Backend Health Awareness** — Controller detects missing Service or zero-endpoint backends, sets status phase/conditions accordingly, emits warning events, and requeues for automatic recovery.
- **Runtime Route Conflict Guard** — Controller detects gateway+host+path conflicts and marks one side `Degraded` with reason `RouteConflict` while allowing the selected winner to reconcile.
- **Certificate Expiry Tracking** — Controller inspects Gateway HTTPS TLS `certificateRefs` secrets and reports `CertificateHealthy` condition (`CertificateHealthy`, `CertificateExpiring`, `CertificateExpired`, `CertificateSecretMissing`, etc.).
- **Custom Prometheus Metrics** — `route_reconcile_total`, `route_status_phase`, `route_backend_health`, `route_managed_resources` exported by controller-runtime metrics endpoint.
- **Rate Limiting** — `spec.rateLimit` now auto-generates Istio EnvoyFilter local token-bucket rate limiting (requests per unit with optional burst) for route hosts.
- **Canary / Traffic Splitting** — `spec.canary` now supports weighted primary/secondary splits plus probe-driven automatic rollback to stable on consecutive canary 5xx responses.
- **Retry Policy** — `spec.retries` field configures Istio `VirtualService` retry policy (`attempts`, `perTryTimeout`, `retryOn`) across all generated HTTP routes.
- **Header Manipulation** — `spec.rules[].headers` supports request/response header add/remove/set and is translated into Gateway API header modifier filters plus Istio `VirtualService` header operations.
- **Authentication Integration** — `spec.auth` now auto-generates Istio `RequestAuthentication` and host/path-scoped `AuthorizationPolicy` for JWT-protected traffic.

## Architecture

```
User creates Route CR (namespaced)
         │
         ▼
┌─────────────────────────┐
│   Route Controller      │
│   (reconcile loop)      │
└─────────┬───────────────┘
          │ generates (based on spec)
          ▼
┌─────────────────────────────────────────────────┐
│  Same Namespace (ownerRef → auto GC)            │
│  ┌────────────┐  ┌────────────────────────┐     │
│  │ HTTPRoute  │  │ HTTPRoute (redirect)   │     │
│  │ (per rule) │  │ (per unique host)      │     │
│  └────────────┘  └────────────────────────┘     │
│  ┌────────────────────┐                         │
│  │ VirtualService     │ (if timeout or cors)    │
│  └────────────────────┘                         │
├─────────────────────────────────────────────────┤
│  Gateway Namespace (labels → finalizer cleanup) │
│  ┌────────────────────┐  ┌──────────────┐       │
│  │ DestinationRule    │  │ EnvoyFilter  │       │
│  │ (if HTTPS backend) │  │ (if body sz) │       │
│  └────────────────────┘  └──────────────┘       │
└─────────────────────────────────────────────────┘
```

## Prerequisites

- **Istio** v1.23+ installed with Gateway API support enabled
- **Gateway API CRDs** installed (`kubectl get crd gateways.gateway.networking.k8s.io`)
- **A Gateway resource** deployed (e.g., in `istio-system`) with HTTPS and HTTP listeners
- **Kubernetes** v1.28+
- **cert-manager** (optional, required if using `certManager.enabled=true` in Helm) with a working `ClusterIssuer` — verify with `kubectl get clusterissuer` and ensure all cert-manager pods are Ready (`kubectl get pods -n cert-manager`). For local/dev clusters (Kind, k3d), a `selfSigned` ClusterIssuer works.
- **external-dns** configured with `--source=gateway-httproute` to automatically create DNS records from HTTPRoute hostnames
- A wildcard or per-host TLS certificate referenced by the Gateway
- **Kind/local clusters:** Ensure adequate inotify limits (`fs.inotify.max_user_watches=1048576`, `fs.inotify.max_user_instances=512`) to avoid "too many open files" errors in system pods

## Limitations

- **Gateway TLS certificate dependency** — The operator assumes the target Gateway already references a valid wildcard or per-host TLS certificate. It does not currently provision or rotate Gateway TLS certificates itself.
- **Local-only rate limiting today** — Current `spec.rateLimit` behavior is implemented through local Envoy token-bucket limits. External/global distributed rate limiting backends are not implemented yet.
- **Single-cluster scope** — Reconciliation targets resources in the current cluster only. Multi-cluster Route intent publishing and per-target status isolation are not available yet.

Example minimal Gateway:
```yaml
apiVersion: gateway.networking.k8s.io/v1
kind: Gateway
metadata:
  name: istio-gateway
  namespace: istio-system
spec:
  gatewayClassName: istio
  listeners:
    - name: http
      port: 80
      protocol: HTTP
      hostname: "*.example.com"
      allowedRoutes:
        namespaces:
          from: All
    - name: https
      port: 443
      protocol: HTTPS
      hostname: "*.example.com"
      tls:
        mode: Terminate
        certificateRefs:
          - name: wildcard-tls-cert
      allowedRoutes:
        namespaces:
          from: All
```

## Quick Start

### Mode Selection

- **Controller mode (baseline):** Use the core `Route` workflow for standard routing generation with minimal operational overhead.
- **Operator mode (advanced):** Use baseline `Route` workflows plus optional advanced features (webhooks, health gates, rollout protections, and policy automation) as needed.

### Install with Helm

```bash
helm install igro oci://ghcr.io/peishuli/charts/igro \
  --version 0.1.0 \
  -n igro-system --create-namespace
```

To enable automatic webhook certificate provisioning via cert-manager:

```bash
helm install igro oci://ghcr.io/peishuli/charts/igro \
  --version 0.1.0 \
  -n igro-system --create-namespace \
  --set certManager.enabled=true \
  --set certManager.issuerRef.name=letsencrypt \
  --set certManager.issuerRef.kind=ClusterIssuer
```

To customize resources, replicas, or disable webhooks, see [`charts/igro/values.yaml`](charts/igro/values.yaml).

### Upgrade with Helm

```bash
helm upgrade igro oci://ghcr.io/peishuli/charts/igro \
  --version 0.2.0 \
  -n igro-system
```

### Publishing a New Chart Version

The chart is automatically published to `oci://ghcr.io/peishuli/charts/igro` by GitHub Actions when a version tag is pushed:

```bash
# 1. Bump version in charts/igro/Chart.yaml
# 2. Commit and tag
git add charts/igro/Chart.yaml
git commit -m "bump chart to 0.2.0"
git tag v0.2.0

```

### Install with Make (development)

```bash
# Install CRD
make install

# Deploy operator
make deploy IMG=peishu/istio-gateway-api-operator:v0.2.0
```

### Create a Route

```yaml
apiVersion: istio-gateway-api-operator.io/v1alpha1
kind: Route
metadata:
  name: my-app
  namespace: my-namespace
spec:
  rules:
    - host: my-app.example.com
      backend:
        serviceName: my-service
        servicePort: 8080
```

### Check status

```bash
kubectl get routes -A
kubectl describe route my-app -n my-namespace
```

## CRD Schema

```go
type RouteSpec struct {
    Rules       []RouteRule   `json:"rules"`
    SSLRedirect *bool         `json:"sslRedirect,omitempty"`   // default: true
    Timeout     string        `json:"timeout,omitempty"`       // e.g., "60s"
    MaxBodySize string        `json:"maxBodySize,omitempty"`   // bytes, e.g., "104857600"
    CORS        *RouteCORS    `json:"cors,omitempty"`
    Gateway     *RouteGateway `json:"gateway,omitempty"`       // default: istio-gateway/istio-system
}

type RouteRule struct {
    Host    string       `json:"host"`
    Path    string       `json:"path,omitempty"`     // default: "/"
    Backend RouteBackend `json:"backend"`
}

type RouteBackend struct {
    ServiceName string `json:"serviceName"`
    ServicePort int32  `json:"servicePort"`
    Protocol    string `json:"protocol,omitempty"` // HTTP (default) or HTTPS
}
```

### Design decisions

- `SSLRedirect` uses `*bool` pointer to distinguish "not set" (defaults to true) from explicit `false`
- kubebuilder markers generate validation, defaults, and printer columns
- Status uses standard `metav1.Condition` for Ready/Synced reporting

## What Gets Generated

| Resource | When | Where |
|----------|------|-------|
| **HTTPRoute** (per rule) | Always | Route's namespace |
| **HTTPRoute redirect** (per unique host) | `sslRedirect: true` (default) | Route's namespace |
| **VirtualService** (shared) | `timeout` or `cors` is set | Route's namespace |
| **DestinationRule** | Any rule has `protocol: HTTPS` | Gateway namespace |
| **EnvoyFilter** (per rule) | `maxBodySize` is set | Gateway namespace |

## Resource Lifecycle

- **Same-namespace resources** (HTTPRoute, VirtualService): Use `controllerutil.SetControllerReference()` — Kubernetes GC handles deletion automatically
- **Cross-namespace resources** (DestinationRule, EnvoyFilter in gateway namespace): Use labels (`istio-gateway-api-operator.io/managed-by`, `istio-gateway-api-operator.io/route-name`) + finalizer-based cleanup

| API Group | Resources | Verbs |

| `istio-gateway-api-operator.io` | routes, routes/status, routes/finalizers | full CRUD |

## Roadmap

- [ ] **Per-Route Progressive Delivery Analysis** — Add request/error-rate based canary promotion and automatic rollback using Prometheus queries and policy thresholds.
- [ ] **Global Rate Limiting** — Extend `spec.rateLimit` to support external/global rate limiting backends in addition to local token buckets.
- [ ] **Policy Templates and Presets** — Provide reusable `RoutePolicy` presets (security, retries, headers, limits) that Routes can reference by name.
- [ ] **Gateway Compatibility Validation** — Validate listener protocol/hostname/allowedRoutes compatibility and surface explicit readiness reasons when Gateway capabilities do not match Route intent.
- [ ] **Dependency and Drift Status** — Add status sub-fields for managed-resource drift detection and last-applied generation per child resource.
- [ ] **Safe Rollout Modes** — Add `spec.rolloutStrategy` options (all-at-once, staged, canary-first) for controlled reconciliation of complex Route changes.
- [ ] **Operator Metrics Expansion** — Add SLO-oriented metrics (reconcile latency histograms, webhook denials, rollback counters) and example dashboards.
- [ ] **Multi-Cluster Targeting** — Support publishing Route intent to one or more remote clusters with per-target status and failure isolation.
